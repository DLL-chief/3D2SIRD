# 3D2SIRD

Веб-приложение, которое берёт 3D-модель и рендерит её как автостереограмму
(SIRD, Single Image Random Dot Stereogram — «Magic Eye»). При правильном
взгляде на картинку модель видна как настоящий объём без очков и
дополнительного железа.

**Живой стенд:** https://dll-chief.github.io/3D2SIRD/ (собирается и
деплоится автоматически из `main` — см. `.github/workflows/deploy-pages.yml`).

## 1. Что это за проект

- **Бизнес-цель:** экспериментальный/образовательный инструмент — показать
  3D-объект как стереограмму на обычном экране или распечатке. Целевая
  аудитория — те, кто хочет получить стереограмму из своей модели (ученики,
  преподаватели, любители), без установки софта.
- **Стадия:** прототип. Кода ещё нет — есть только архитектура и
  документация; код пишет Claude Code по `STATUS.md`.
- **Владелец:** Дима (DLL-chief) — принимает продуктовые и технические
  решения.

## 2. Стек

| Слой | Технология | Версия |
|---|---|---|
| Frontend | Vite + vanilla JS (ES modules), без фреймворка | Vite 5+ |
| 3D | Three.js | r165+ (последняя стабильная на момент старта) |
| Генерация SIRD | чистый JS + Canvas 2D / ImageData, в Web Worker | — |
| Backend | нет | — |
| БД | нет | — |
| Инфраструктура | GitHub Actions → GitHub Pages (статика) | — |

Чего в стеке НЕТ и почему:

- **Нет фреймворка (Vue/React).** UI — несколько слайдеров и кнопок,
  фреймворк здесь только добавил бы сборку и зависимости. Не добавлять без
  согласования с владельцем.
- **Нет TypeScript.** Осознанно на стадии прототипа, чтобы не тратить время
  на типизацию Three.js. Может быть пересмотрено отдельным ADR.
- **Нет бэкенда.** Всё считается в браузере; модель пользователя никуда не
  отправляется. Это продуктовое свойство (приватность, работа офлайн), а не
  временное упрощение.
- **WebGPU не используется в MVP.** Генератор SIRD — на CPU в Web Worker;
  GPU-версия отложена (см. `STATUS.md`, беклог).

## 3. Быстрый старт (локально)

```bash
git clone https://github.com/DLL-chief/3D2SIRD.git
cd 3D2SIRD
npm install
npm run dev
```

Секретов и переменных окружения у проекта нет — `.env.example` не нужен.

## 5. Кому и как читать этот репозиторий

- **Человек** начинает с этого файла, дальше — `docs/architecture.md`.
- **ИИ-агент** сначала читает `AGENTS.md`/`CLAUDE.md`, потом `STATUS.md` —
  чтобы понимать, что уже сделано и что делать дальше, а не предлагать
  заново то, что уже решено.
- Локальные `README.md` внутри модулей (`src/<module>/README.md`) читаются
  ТОЧЕЧНО, когда агент работает именно в этом модуле — не при каждом запуске.

## 6. Как вносить изменения

1. Ветка от `main` (`feature/...`, `fix/...`).
2. PR с описанием «что и зачем» по-русски.
3. Обязательно: обновить `STATUS.md`, если задача меняет активное состояние
   работы (см. `AGENTS.md`, п.1).
4. CI зелёный → мёрдж.
