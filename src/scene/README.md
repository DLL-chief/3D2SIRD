# scene — 3D-сцена

## Назначение

Загрузить модель (GLB через `GLTFLoader`, либо встроенная демо-геометрия),
поместить её в сцену с камерой и `OrbitControls`, дать пользователю
покрутить. НЕ отвечает за рендер глубины и за материалы — модель
отображается любым простым материалом только для навигации.

## Инварианты этого модуля

- После загрузки модель центрируется по bounding box и масштабируется так,
  чтобы вписаться в единичный куб. Остальные модули (`depth/`) полагаются
  на это при выборе near/far камеры.
- Модуль отдаёт наружу `{ scene, camera, controls }` и ничего больше;
  `depth/` не должен лезть внутрь иерархии объектов.
- Управление можно повесить на несколько элементов сразу
  (`attachControls`): предпросмотр сцены и сама стереограмма вращают одну
  камеру. Из-за этого панорама выключена — цель у каждого набора
  контролов своя, и сдвиг одной развёл бы наборы между собой.

## Точка входа для чтения

`src/scene/index.js` — `createScene(domElement)` (сцена, камера,
OrbitControls), `loadModel(file | url)` (GLB через `GLTFLoader`),
`createDemoModel(kind)` (встроенная геометрия) и `showModel(scene, model)`
(замена модели с освобождением буферов). Вписывание в единичный куб —
в чистом `fit.js`, он покрыт тестами в Node (`__tests__/`), сам рендер и
загрузка проверяются только в браузере.

## Известные ловушки

- **Затухание OrbitControls ломает пересчёт по событию.** С
  `enableDamping = true` камера едет по инерции ещё около четырёх секунд
  после отпускания кнопки, и событие `change` сыплется каждый кадр всё это
  время: дебаунс на нём сбрасывается на каждом кадре и не срабатывает
  вообще — стереограмма просто не обновлялась. Поэтому затухание выключено,
  а пересчёт идёт по событию `end` (оно приходит и на отпускание кнопки, и
  на прокрутку колеса). Свои `update()` OrbitControls вызывает из
  обработчиков сам, в цикле отрисовки он не нужен.
- **Симметричная модель маскирует поломку вращения.** Сфера выглядит
  одинаково со всех сторон, поэтому «карта глубины не изменилась после
  вращения» на ней — норма, а не дефект. Проверять надо на заведомо
  асимметричном объекте (тор-узел, перекладина со шаром).
- **Трансформация вписывания вешается на обёртку-группу, а не на модель.**
  У корня GLTF может быть собственный поворот или смещение; переписать его
  своим `scale`/`position` значило бы развернуть модель непредсказуемо.
- **Материалы из файла заменяются на `MeshNormalMaterial`.** PBR-материалы
  GLTF потребовали бы света и окружения, а этот модуль отвечает только за
  навигацию — для карты глубины материал всё равно подменяется в `depth/`.
  Заменённые материалы освобождаются, иначе каждая загрузка оставляла бы
  их в памяти GPU.
- **Тестовый GLB не коммитится.** Файл для проверки загрузки генерируется
  на ходу через `GLTFExporter` (в Node ему нужна заглушка `FileReader`) —
  так проверяется и разбор файла, и вписывание модели «неудобного»
  масштаба, без бинарников в репозитории (`AGENTS.md`, п.6).
