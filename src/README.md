# src/ — конвенция модульных README

Каждый АКТИВНЫЙ модуль (папка с изолированной логикой) несёт собственный
`README.md` внутри своей папки, а не полагается на корневой `README.md` или
`docs/architecture.md`.

## Зачем это отдельно от docs/architecture.md

`docs/architecture.md` даёт карту СВЕРХУ — как модули связаны между собой.
Локальный `README.md` модуля объясняет, что происходит ВНУТРИ него: с чем
агенту нужно считаться при правке именно этого куска кода. Агент, работающий
над задачей в одном модуле, должен иметь возможность прочитать ТОЛЬКО этот
файл и получить достаточно контекста для точечной правки.

## Что писать в README модуля

- Назначение модуля (одна-две фразы).
- Неочевидные инварианты и ограничения именно этого модуля.
- Точки входа: с какого файла/функции начинать чтение.
- Известные ловушки, набитые на практике — что именно ломалось и почему.

## Чего НЕ писать

- Общие правила стиля кода и коммитов — они в `AGENTS.md`.
- Бизнес-контекст всего продукта — он в корневом `README.md`.

## Модули

- `scene/` — Three.js: модель, камера, управление.
- `depth/` — карта глубины из сцены.
- `sird/` — генератор стереограммы (без Three.js).
- `ui/` — контролы, превью, экспорт.
