# depth — карта глубины

## Назначение

Отрендерить `scene`+`camera` в `WebGLRenderTarget` с override-материалом,
пишущим линейную глубину, прочитать пиксели и вернуть `DepthMap` по
контракту из `docs/api_contracts.md`. Опционально — размытие карты.

## Инварианты этого модуля

- Нормализация диапазона — по фактическим min/max глубины модели в кадре,
  НЕ по near/far камеры. Иначе модель, занимающая 10 % диапазона камеры,
  даст плоский рельеф.
- Фон (пиксели, где нет геометрии) = ровно 0. Не «почти 0», не min по
  модели — иначе объект «тонет» в шуме стереограммы.
- Результат в `[0, 1]`, 1 — ближе к зрителю. Инверсия здесь не делается.
- Разрешение render target задаётся вызывающей стороной (`ui/`), а не
  берётся из размера окна.
- `floor` укладывает модель в `[floor, 1]`, оставляя фон нулевым: у силуэта
  сохраняется ступенька, и предмет читается перед фоном. Цена — рельеф
  модели получает только `1 − floor` диапазона диспаратности, то есть
  ступеней рельефа становится меньше (компенсируется ростом E).

## Точка входа для чтения

`src/depth/index.js` — функция
`renderDepth(renderer, scene, camera, { width, height, blur, floor })`.
Внутри неё только работа с Three.js; математика вынесена в чистые
`normalize.js` и `blur.js` — они тестируются в Node, без WebGL
(`__tests__/`). Сам рендер в Node не проверить, только в браузере.

## Известные ловушки

- **`readRenderTargetPixels` отдаёт строки снизу вверх.** Начало координат
  WebGL — левый нижний угол, а `DepthMap` идёт сверху вниз, как
  `ImageData` (`docs/api_contracts.md`, п.1). Без переворота карта
  приходит в `sird/` зеркальной по вертикали, и на симметричной модели
  этого не видно — проверять наклонённой плоскостью, у которой верх кадра
  ближе к камере (тогда первая строка должна быть ≈1, последняя ≈0).
- **Размытие не должно затягивать модель в фон.** Первая версия усредняла
  всё подряд, и при `blur: 2` с `floor: 0.35` минимум модели падал до
  `0.014` вместо `0.35`: ступенька силуэта размазывалась в пологую «юбку»,
  и предмет снова читался холмом на стене. Поэтому фон (нули) в
  усреднении не участвует и остаётся нулём — силуэт остаётся резким
  намеренно, окклюзию на нём обрабатывает `sird/`. Сглаживаются только
  изломы рельефа внутри модели.
- **Без `floor` самая дальняя видимая точка модели нормализуется в 0, как
  фон.** Прямое следствие нормализации по min/max: диапазон растягивается
  на весь `[0, 1]`, поэтому у дальнего края силуэта глубина совпадает с
  фоновой, и выпуклая модель читается холмом, а не предметом. Лечится
  `floor` (см. инварианты), а не правкой нормализации.
- **Число ступеней рельефа задаётся не только `sird/`, но и этим
  модулем.** Сепарация в `sird/` округляется до целых пикселей, поэтому
  всего ступеней `≈ E·μ / (2(2−μ)) + 1`, а модели из них достаётся доля
  `1 − floor`. Замеры на сфере: при `E=90, μ=1/3, floor=0.35` — 8
  ступеней (гладкий купол виден террасами), при `E=300, μ=0.5` — 34. На
  дефолтах контракта (`E=180, μ=0.45`) — 27 без подъёма и 18 при
  `floor=0.35`. Если рельеф выглядит ступеньками, дело не в карте глубины,
  а в этой арифметике.
- **`camera.aspect` правится на время рендера.** Если аспект камеры не
  совпадает с `width/height` карты, кадр вышел бы растянутым, поэтому
  функция подменяет `aspect`, дёргает `updateProjectionMatrix()` и
  возвращает прежнее значение. У ортографической камеры не трогается.
- **`MeshDepthMaterial` из Three.js пишет нелинейную (перспективную)
  глубину** — поэтому здесь свой `ShaderMaterial` с `-viewPosition.z`.
  С нелинейной глубиной дальняя половина модели схлопнулась бы почти в
  одно значение.
- **Float-таргет читается по 4 компонента.** `readRenderTargetPixels`
  ждёт буфер под RGBA, поэтому таргет создаётся как
  `RGBAFormat` + `FloatType`, а глубина берётся из канала `r`.
