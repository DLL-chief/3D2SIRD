# ADR-003: Генератор стереограммы — сначала CPU в Web Worker, GPU потом

**Статус:** Принято
**Дата:** 2026-09-14
**Авторы:** Дима

## Контекст

Классический алгоритм автостереограммы (Thimbleby–Inglis–Witten) — строго
последовательный внутри строки: цвет пикселя зависит от уже раскрашенных
пикселей левее, а ссылки `same[x]` перезаписываются при окклюзии. Это
плохо ложится на фрагментный шейдер, где каждый пиксель считается
независимо. Есть приближённые GPU-варианты (без строгой окклюзии, с
фиксированным числом итераций), но они дают артефакты на резких перепадах
глубины.

Хочется два режима: (а) качественная картинка по кнопке, (б) в перспективе —
стереограмма в реальном времени при вращении модели.

## Решение

MVP делает только (а): точный TIW-алгоритм на CPU, в Web Worker, чтобы не
замораживать UI. Карта глубины передаётся в Worker через transfer буфера.

Three.js используется только для получения карты глубины; генератор —
отдельный модуль `src/sird/` без зависимости от Three.js, с тестом на
синтетической карте.

## Альтернативы

- **Сразу шейдер/WebGPU compute.** Отклонено для MVP: сложнее отлаживать,
  WebGPU не везде доступен, а корректность окклюзии — главный фактор
  «читаемости» стереограммы глазом. Сначала нужен эталон, с которым потом
  сравнивать GPU-версию.
- **CPU в главном потоке.** Отклонено: 1920×1080 — около 2 млн пикселей,
  при перегенерации по каждому движению слайдера UI будет подвисать.

## Последствия

- `src/sird/` проектируется как чистая функция
  `(DepthMap, SirdParams) → ImageData` (контракт в `docs/api_contracts.md`),
  чтобы GPU-версия могла реализовать тот же контракт и сравниваться с
  CPU-эталоном попиксельно/по метрике.
- Режим реального времени не обещается в MVP; если понадобится — новый ADR
  со ссылкой на этот.
