# ADR-001: Репозиторий — единый источник правды

**Статус:** Принято
**Дата:** 2026-09-14
**Авторы:** Дима

> Унаследовано из `vibecoders/project-template` (там — self-hosted GitLab).
> Для этого проекта хостинг — GitHub, суть решения не меняется; имя файла
> сохранено ради сквозной нумерации с шаблоном.

## Контекст

Проект ведут одновременно люди и ИИ-агенты (Claude Code, агенты через
MCP-коннекторы). Без явного правила о том, где лежит истина о состоянии
проекта, агенты и разработчики расходятся: код существует в
незакоммиченном виде, решения принимаются в переписке и никем не переносятся
в документацию, у разных участников — разные версии «текущего плана».

## Решение

Git-репозиторий на GitHub — **единственный источник правды** для проекта,
как для людей, так и для ИИ-агентов:

- Код, документация (`docs/`), состояние работы (`STATUS.md`) и решения
  (`docs/adr/`) живут ТОЛЬКО в репозитории. Всё, что не закоммичено, не
  существует для следующей сессии.
- Агент, приступающий к задаче, обязан свериться с `STATUS.md` и `docs/`,
  а не с памятью предыдущего диалога.
- Решение, принятое в чате с агентом, но не зафиксированное файлом в
  репозитории, — не принято и будет предложено заново.
- Слияние — только через Pull Request.

## Альтернативы

- **Внешняя wiki.** Отклонено: документация и код расходятся, потому что
  нет единого PR, фиксирующего оба изменения разом.
- **Память агента или история чата как источник состояния.** Отклонено: не
  переживает новую сессию, не видна остальным, не версионируется.

## Последствия

- Каждый значимый вывод рабочей сессии агента обязан осесть файлом в
  репозитории.
- `STATUS.md` обновляется по завершении каждой задачи (`AGENTS.md`, п.1).
- Новые архитектурные решения — следующие ADR по той же схеме, нумерация
  сквозная; принятый ADR не правится задним числом.
