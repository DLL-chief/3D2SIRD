# ADR-002: Vite + vanilla JS, без UI-фреймворка и без бэкенда

**Статус:** Принято
**Дата:** 2026-09-14
**Авторы:** Дима

## Контекст

Нужно веб-приложение: загрузить 3D-модель, покрутить, сгенерировать
стереограмму, скачать. UI — один canvas, десяток контролов. Основная
сложность — в Three.js и алгоритме стереограммы, а не в интерфейсе.
Команда обычно работает на Vue 3 + Laravel, поэтому вопрос «брать ли
привычный стек» стоял явно.

## Решение

- Сборка — Vite, код — ES-модули на vanilla JS, DOM руками.
- Three.js — единственная runtime-зависимость.
- Бэкенда нет: рендер и генерация полностью в браузере, деплой — статика
  на GitHub Pages.

## Альтернативы

- **Vue 3.** Отклонено для MVP: реактивность нужна для трёх слайдеров, а
  цена — второй слой абстракции над canvas/WebGL, где Vue только мешает
  (управление жизненным циклом Three.js вне реактивной модели). Если UI
  разрастётся (пресеты, галерея, история) — пересмотреть новым ADR.
- **Laravel-бэкенд для генерации.** Отклонено: генерация стереограммы на
  CPU занимает десятки миллисекунд для 1080p — сеть добавит больше, чем
  сэкономит. Плюс приватность: модель пользователя не покидает браузер.
- **TypeScript.** Отложено, не отклонено: на прототипе типизация Three.js
  съедает время; при росте — отдельный ADR.

## Последствия

- Нет роутинга, глобального состояния, компонентной системы — и не должно
  появиться «по привычке». Появление такой потребности = сигнал
  пересмотреть это ADR.
- Тесты — только для `src/sird/` (чистая функция), UI тестируется руками
  в браузере.
