# Контракты между модулями

> Сетевого API у проекта нет. Здесь зафиксированы форматы данных на
> границах модулей — прежде всего `depth → sird`, потому что через неё
> модули разрабатываются и тестируются независимо. Любое изменение
> формата — правка этого файла в том же PR.

## 1. DepthMap (выход `depth/`, вход `sird/`)

```js
{
  width:  number,        // px
  height: number,        // px
  data:   Float32Array   // length = width * height, построчно сверху вниз
}
```

- Значения в диапазоне `[0, 1]`. `0` — фон / самая дальняя точка,
  `1` — ближайшая к зрителю. Значения вне диапазона — ошибка `depth/`, а не
  повод для `sird/` их клампить.
- Порядок строк — как у `ImageData` (первая строка — верх изображения).
- Буфер передаётся в Worker через transfer (`postMessage(msg, [data.buffer])`),
  после чего на стороне отправителя он пуст — `depth/` должен рендерить
  заново, а не переиспользовать.

## 2. SirdParams (вход `sird/`)

```js
{
  eyeSeparation: number,   // E, px; типично 140–240, по умолчанию 180
  depthStrength: number,   // μ, 0 < μ < 1; по умолчанию 0.45
  crossEyed:     boolean,  // true — перекрёстный взгляд (инверсия глубины)
  pattern:       Pattern   // см. п.3
}
```

Дефолты подобраны владельцем глазами на стенде (обычный десктопный монитор,
2026-09-15) и заменили исходные `E=90`, `μ=1/3`. Причина замены не в удобстве
сведения, а в разрешении рельефа: сепарация округляется до целых пикселей,
поэтому всего ступеней рельефа `≈ E·μ / (2(2−μ)) + 1`. При `E=90, μ=1/3`
ступеней 10 — гладкая сфера раскладывается концентрическими террасами и
читается вытянутым холмом; при `E=180, μ=0.45` их 27 (сепарация 64..90 px).
Значение E зависит от физического размера пикселя, поэтому на экране с сильно
другим DPI его придётся менять — калибровка под DPI остаётся открытым
вопросом (`docs/architecture.md`, п.5).

## 3. Pattern (вход `sird/`)

Один из двух вариантов:

```js
{ type: 'noise', color: boolean }
```
Случайные точки; `color: false` — чёрно-белые, `true` — цветные.
Генерируются внутри `sird/` детерминированно от seed (для тестов) —
seed передаётся как `seed: number`, по умолчанию `Date.now()`.

```js
{
  type: 'image',
  data: ImageData,
  mode: 'strip' | 'drift' | 'squeeze',  // по умолчанию 'strip'
  mirror: boolean,                      // по умолчанию false
  driftPerRow: number                   // только для 'drift', px на строку,
}                                       // по умолчанию 0.7
```

Пользовательская текстура. Масштабирование — задача `ui/`, не `sird/`;
здесь только выборка. Неизвестный `mode` — ошибка, а не молчаливый откат.
В image-режимах `seed` не участвует вообще: результат зависит только от
текстуры, режима и E.

**Период полосы — сепарация фона `round(E/2)`, а не `E`.** При `z = 0`
формула сепарации даёт `E/2` при любом μ (μ входит только вместе с `z`),
поэтому именно с таким шагом повторяется узор на фоне, и ровно столько
столбцов картинки видно в кадре: из полосы шириной `E` половина столбцов
не попадает в кадр вовсе — замерено
(`src/sird/__tests__/pattern-image.test.js`). Сепарацию режимы не меняют:
период на фоне одинаков во всех трёх (`__tests__/pattern-modes.test.js`).

Режимы (все — про выборку `colorAt(x, y)` для свободных пикселей):

| `mode` | что берётся из картинки |
| --- | --- |
| `'strip'` | полоса от левого края шириной в период, тайлится |
| `'drift'` | своя полоса на каждую строку: `srcX0 = round(y · driftPerRow)` |
| `'squeeze'` | вся картинка, сжатая по горизонтали до ширины полосы |

- По обеим осям тайлинг идёт **отражением** (ping-pong:
  `y' = y mod 2h`, при `y' ≥ h` → `2h − 1 − y'`), а не по модулю. При
  повторе по модулю на каждом стыке стоит скачок с последнего
  столбца/строки картинки на первый, и в стереограмме он читается ложной
  ступенькой глубины.
- `'drift'` сдвигает начало полосы по строкам, поэтому повторение
  перестаёт читаться обоями, а картинка расходуется по всей ширине
  (замер: 244 из 256 уровней против 61 у `'strip'`). Сдвиг зависит от
  номера строки, а не от номера строки внутри полосы кадра — для расчёта
  полосами в воркерах генератору передаётся `rowOffset` (п.1, `pool.js`).
- `'squeeze'` берёт ближайшего соседа (`srcX = floor(index / период ·
  width)`), без билинейной интерполяции: она мылит зерно, а стерео
  читается как раз по высоким частотам. Поэтому уменьшать картинку до
  ширины полосы должен `ui/` (canvas усредняет пиксели), а не генератор.
- `mirror` склеивает полосу из половины и её отражения, чтобы соседние
  копии стыковались без разрыва; работает во всех трёх режимах. Цена —
  вдвое меньше исходных столбцов в кадре.
- **`ui/` обязан дать картинку высотой в кадр.** Отражение по вертикали —
  запас на случай, когда картинка короче кадра, а не рабочий режим: у
  фотографии, уменьшенной под ширину полосы, высота выходит в десяток раз
  меньше кадра, и тайлинг размножает миниатюру зеркальными копиями.
  Поэтому масштаб задаётся высотой кадра, а по ширине берётся срез —
  `src/ui/texture.js`, `sliceGeometry()`.
- Ширина картинки, которую ждёт генератор: `'strip'` — ширина полосы
  (`round(E/2)`, при `mirror` — `ceil(period/2)`), `'drift'` — полоса плюс
  `ceil(height · driftPerRow)`, `'squeeze'` — ровно ширина полосы (сжатие
  по ширине — за `ui/`, выборка ближайшим соседом в генераторе его не
  заменяет). Картинка шире не ломает ничего, просто лишние столбцы не
  попадут в кадр; уже — генератор дотайлит полосу отражением.

## 4. Выход `sird/`

`ImageData` с `width`/`height`, равными входной карте глубины. Формат
сообщения из Worker:

```js
{ type: 'done', image: ImageData, ms: number }   // ms — время генерации
{ type: 'error', message: string }
```

## 5. Подложка-фотография (вход `mix/`)

Постобработка готового кадра (ADR-005). Обе функции чистые, на входе и
выходе — сырые RGBA:

```js
blurRgba({ width, height, data }, radius, passes = 2) → Uint8ClampedArray
modulate(stereo, photo, amount) → Uint8ClampedArray
```

- `photo` — RGBA-буфер **того же размера, что кадр**; вписывание картинки
  в кадр («по большей стороне», с обрезкой лишнего) — задача `ui/`.
- `amount` — сила подложки `a ∈ [0, 1]`. Формула
  `out = stereo · (1 − a + a · photo/255)`: множитель не больше 1, поэтому
  светлые точки не упираются в 255, и не меньше `1 − a`, поэтому под самым
  тёмным пятном фотографии у точек остаётся контраст `255·(1 − a)`.
- Альфа на выходе всегда 255.
- Замеры, границы и дефолты (`a = 0.6`, радиус 8) — `docs/adr/005`.

## 6. Синтетическая карта для тестов

`sird/` обязан корректно работать на карте «полусфера радиусом `0.4·min(w,h)`
в центре над плоским фоном 0». Эталонное изображение для теста генерируется
с фиксированным `seed` и хранится в `src/sird/__fixtures__/` (см. беклог в
`STATUS.md`).
